# V62.1 旧面单组件遗漏修复

修复位置是传统扫码入库内的 `tdV58PanelHTML()` / `#tdV58PreviewPanel`，并非另一个高清拍照表单。在面单文字下方、件数上方直接渲染客户搜索、客户姓名、手机号码。控件不以照片、识别结果或成功状态为显示条件。

选择已有客户自动填姓名/电话；手填或修改后用现有 V62 原子接口重新匹配，冲突拒绝，不覆盖旧档案。无需OCR、照片或运单号即可经人工确认入库；无运单号生成独立包裹编号。默认一件，原件数/重量和照片保存选项保留；新增可关闭的照片OCR选项，关闭后照片仍可在入库成功时保存。

保留旧OCR路径的置信度、独立条码核对、隐藏号码/冲突拦截和创建权限。新手动路径使用明确确认、现有角色权限和幂等请求；离线禁止写入，结果丢失通过V62状态接口核实，未核实前拦截重复和并行扫码入库。

实际DOM/渲染测试覆盖主页高清入口、智能扫码中心→扫码入库、直接重新进入页面；逐一断言客户控件首次显示/可编辑、准确DOM顺序，以及未调用OCR。390px移动视口截图验证了旧组件中控件位置。还覆盖已有客户选择/自动填充、手填、改客户清除旧ID、件数3/重量1.275、重量留空、无OCR照片保存、断网、响应丢失与恢复。Chromium/WebKit测试使用真实页面脚本/布局、模拟业务传输，不向正式库写测试数据。保留旧V58及V62浏览器、OCR、扫码、权限/数据库回归。

本次只改前端，复用已安装V62接口，不执行数据库迁移、业务修改/删除、照片清理或Restore，不新增付费服务。未连接iPhone/Android真机，不把移动视口或WebKit测试称为真机验收。人工验收：打开传统扫码详情，未选照片即看到三个客户控件；选客户或手填、改件数/重量并确认；关闭OCR后验证照片保存选项。
