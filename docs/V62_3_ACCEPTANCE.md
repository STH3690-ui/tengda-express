# V62.3 传统扫码 / V58统一紧凑界面

实际修改`tdScanPage()`的传统扫码入口和内部`tdV58PanelHTML()`，不是仅改智能拍照页面。传统默认顺序：扫码摄像头→扫码/相册/手电筒→运单号→折叠客户搜索→姓名/手机并排→件数/重量并排→单行备注→金色确认。智能拍照和传统扫码复用`tdV623Fields()`生成同一套客户和包裹字段，保留各自原ID/事件处理及黑金样式。

面单大文字框、OCR勾选、自动入库、创建客户、照片保存、提示音、摄像头选择和停止扫码统一放入高级设置。批量扫码/逐条客户编辑/照片上传/批量确认也在高级区，功能保留，默认不重复显示另一套表单。

默认单件界面仍用原扫码校验/数据库查询；成功扫描只把未登记运单放入当前表单、停止预览，直到按确认才调用已有V62人工入库。摄像头不覆盖当前另一条未确认运单。需要连续收集清单时显式开启高级区的批量模式，沿用原队列及批量接口；有未处理清单不能静默关闭批量模式。无运单号、无OCR的手填入库保留。

客户搜索仍为260ms防抖和过期响应保护，选择后收起。备注传入已有V62入库字段。手动改客户/运单/备注要求人工确认，不用旧OCR覆盖人工资料；未改字段的原高置信度+独立条码自动入库仍保留。成功、成功恢复和旧OCR自动成功后清理已办运单，防止把已办运单留作下一件。

测试覆盖实际智能扫码中心→扫码入库→传统入口，320/360/390/430宽度、布局顺序、双列和隐藏高级项、共享字段、相册/扫码/灯按钮、HID单件仅暂存不写入、确认请求包含正确运单/客户/件重/备注、批量模式保留及未办清单保护，以及查询/取件页没有重复扫码ID。保留原V58/V62/V62.1/V62.2、真实WASM OCR、条码、财务/权限和PostgreSQL回归。

无数据库迁移、原业务数据修改/删除、权限变更、Restore或新增付费服务。浏览器测试的业务传输和硬件为模拟；WebKit/手机尺寸不等于iPhone/Android实机。真实扫码对焦、手电筒、相册/PWA/TWA仍需实机验收。
