# V61 高清拍照智能入库

一次员工快门对应一张冻结原图。没有稳定度检测、自动抓拍或连续实时 OCR。成功短暂展示姓名/电话，1.4 秒后回预览；下一件仍须再按快门。异常保留图片供核对，近期同客户/面单要求确认另一件。

优先 ImageCapture.takePhoto 原始照片；不支持时读取 videoWidth/videoHeight 的原始高清摄像头帧，绝不读取 CSS 缩略图。原图不足 1920×1080 时提供系统高清相机入口。系统相机图片只在本机处理。原图中对应金框区域裁剪后，有界放大、灰度锐化/对比度、±6° 倾斜校正及二值化，最多三次 OCR、总识别时间上限约65秒。引擎预加载、串行复用，退出/后台/取消时释放。

自动入库要求两种不同处理方式的姓名及号码一致、平均置信度≥95且最低字词≥90；号码纠错、遮挡、虚拟号、仓库/寄件人、歧义均保持人工核对。阈值不是准确率保证。服务器仍检查员工实际权限、客户冲突、仓库电话、重复请求和近期同客户，使用原有原子客户/包裹事务。一件、入库零重量，沿用统一称重及收款/欠款。

## 自动验收

- Node 单元测试和语法检查；V57–V61 临时 PostgreSQL 完整功能、真实并发、质量门槛、权限及失败回滚。
- 托管隔离 tengda-v32-test：V61安装、默认一件、匹配/新建、重复拦截、连续取件及欠款14000/5000/9000、员工隔离和事务回滚；合成记录全部回滚。
- Chromium/WebKit 浏览器：手动快门、冻结先于OCR、两个处理方式一致、成功回预览但不自动拍摄、原始高清照片接口模拟、低分辨率拒绝、错误照片保留/修改、断网禁止提交、响应丢失核实和迟到结果取消。
- 实际同源免费 WASM OCR：六种**合成**图片（括号加号、括号连写、空格、跨行、英文国际号码、4°倾斜），验证解析及预处理/引擎复用。未提供真实快递面单照片；不能宣称已测真实面单准确率。
- 当前开发机器六种格式每种3轮均正确解析，但均未有两轮达到严格自动置信度门槛，因此正确保留人工核对。这不是手机速度或自动入库率承诺。

## 手机待验收（未执行）

1. iPhone Safari、主屏幕 PWA、Android Chrome/TWA 各允许后置相机；停留两秒不自动拍摄；快门大圆按钮可触达、黑金文字清楚。
2. 使用真实面单分别拍括号加号/连写/跨行/英文/中国手机；金框仅包含地址末尾，检查实际原图来源及尺寸、对焦、反光、裁剪对应和声音/震动。Safari不支持原始照片API时确认高清原始帧或系统相机降级。
3. 清晰无冲突资料才自动入库；低置信度、遮挡、仓库/寄件电话及多客户必须保留照片。先在测试环境进行写入验收。
4. 成功姓名电话显示后自动回预览，不会自动再次拍摄；同客户第二件需确认另一件，不重复提交同一件。
5. 断网/弱网、后台切回、拒绝相机、OCR取消、响应丢失恢复；连续20件观察内存/发热/耗时，退出相机灯熄灭。
6. 验证传统条码、人工客户选择、统一称重、付款/欠款及普通员工权限。
