# V62 统一入库

拍照/手动入口和传统扫码清单均支持已有客户姓名/电话搜索与选择，自动填充后可修改。修改客户资料会清除原客户选择，保存时按规范化姓名和完整号码重新匹配；唯一匹配才关联，无冲突且有创建权限才新建。同名异号、同号异名、归档/隐藏客户必须核对，不会覆盖旧客户档案。没有客户资料权限的员工可沿用按姓名选择客户的入库权限，不能搜索或取得隐藏电话号码。

件数默认1，可修改正整数；重量为该条包裹的**总重量**，最多3位小数，留空按未称重保存；备注最多2000字。拍照识别保留V61高清手动快门、严格OCR门槛、失效照片核对与免费本机引擎。传统扫码、手动输入运单、旧面单工具保留。V62主要入库表单和扫码清单使用黑金样式。

取件按登记总重×本次件数/原件数汇总（部分取件为按件均分的参考值）；可重新称重填写实际总重量。只要选中未称重包裹，参考重量不填入最终结算重量，必须统一称重填写。变更取件清单后重新计算，不能沿用旧清单的手工总重量。财务结算仍调用原V57/V32原子取件账务。

## 自动检查

- Node单元测试及语法、静态部署检查。
- 临时PostgreSQL V57–V62：新增迁移失败整体回滚、已有客户/手填规范化匹配、并发重复拦截、件数/小数重量/备注、选客户不更新旧档案、批次逐条事务、迟到请求封存、失败客户/包裹回滚、员工权限/电话号码隐私、统一称重与欠款。
- 托管隔离tengda-v32-test：三件/小数重量入库、唯一匹配不重复建客、防重/质量门槛、连续取件和收款欠款14000/5000/9000、权限/事务回滚；所有合成业务记录回滚。
- Chromium/WebKit：客户选择和可编辑元数据，高清手动快门、成功返回、照片失败人工核对、断网/响应丢失、原始高清图片与低分辨率保护、登记重量汇总/重称/未知重量保护；旧条码、OCR、导航、历史和员工功能回归。

仅新增V62三个RPC和私有RLS请求表，不重跑旧迁移，不更新/删除原有业务记录，不新增服务或收费资源。RPC固定空search_path、撤销PUBLIC/anon执行，服务器检查实际员工权限；请求表不向客户端开放。旧V57/V59请求状态可通过新接口核实，原取件接口保留。

## 发布与恢复

V62迁移单事务、锁5秒/语句60秒超时，测试后先安装新RPC再发布前端。安装失败整体回滚。上线后出现问题应保留新请求和包裹记录，暂停新入库、先核实待完成请求再回退前端或修补状态核实入口；不为界面问题Restore正式库或删除请求记录。官方备份历史证据不等同恢复演练或覆盖后续业务，本次新增结构不依赖整库恢复。
